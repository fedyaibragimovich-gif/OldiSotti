## Confirmed, safely addressed in this PR

1. **Category pagination missing an index (data availability):** `fetchListingsPage` combines `status == active`, `categoryId == ...`, and descending `createdAt`; only the unfiltered index was declared. A missing index sends the query to a bounded 300-record fallback that can omit older category ads. Declare the category composite index *additively*, preserving the existing index. The Firebase index must be deployed and reach READY separately before the production category query can rely on it; a source change alone does not create a cloud index.
2. **Production mobile test ran against a Vercel alias:** the manual E2E workflow's `BASE_URL` pointed to `fedyaibragimovich-gif.vercel.app` rather than the customer's canonical `oldi-sotdi.uz`. Point the workflow at the actual domain. It remains manual and was not run, because it creates production Firebase users/listings and cleanup is best effort.
3. **Dismissed news banner reappeared on component remount:** preserve dismissal only for the current browser session using a versioned key. No changes to account, chat, ad data, payment, or security rules.
4. Added CI source/configuration regressions for the category index, test target and dismissal behavior.

## Remaining risks and required verification (not fixed or claimed fixed)

**Launch blockers requiring real browser/account testing**

- Manually run complete user-journey checks on Android/iOS: registration, password reset, Google/Facebook login, image upload, listing moderation, editing/deletion, and two real accounts exchanging messages. The mobile E2E spec currently returns early from its chat section when a listing is `pending`; a green run in that mode does **not** prove chat works. Approve a controlled test listing through normal moderation before relying on the chat result; do not bypass Firestore rules or publish fabricated inventory.
- Check Firebase authorized domains, Storage rules deployment and permission behavior in the real Firebase project, including existing-user data and account switching.
- Deploy the newly declared category Firestore index through an approved Firebase workflow/console, wait until READY, then run live category cursor smoke tests. The existing `deploy-firestore-rules.yml` only deploys rules, not indexes; do not automatically deploy all indexes without first reviewing existing untracked indexes (Firebase CLI can prompt to delete indexes absent from config).

**Known implementation limits**

- The index-failure pagination fallback reads only the first 300 active records; it is not complete beyond that until required indexes exist. Equal `createdAt` timestamps can also make timestamp-only cursors skip ties; a deterministic document-ID cursor and database index migration need separate tests.
- Conversations store all messages in one Firestore document and notifications are read before client-side sorting/capping; large-scale usage needs paginated message documents and indexed server-side notification queries.
- Upload and deletion cleanup is client-side/best effort; a crashed browser may leave orphan storage objects. Implement an authorized server-side retry job before large-scale usage.
- The posting form supplies a generic favorable description when the seller leaves description blank. Replace with required user-provided description in a separately tested form change, rather than silently changing production form validation here.
- The news banner is currently inside the VIP section and is only mounted on the unfiltered homepage. Decide whether it must also appear on filtered/search pages before changing the main App layout.
- The homepage's Open Graph image was served as a 2.4 KiB indexed PNG and Telegram preview display was not proven. Replacing it must be tested separately with an actual social crawler; no claim made here.
- No real mobile screen reader, network throttling, 5xx load testing, fraud/moderation operations, or verified Click/Payme payment test was performed.
